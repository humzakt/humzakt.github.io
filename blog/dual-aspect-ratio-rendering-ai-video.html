Dual Aspect-Ratio Rendering: Synchronizing 16:9 Widescreen and 9:16 Portrait AI Ads

By Humza Tareen August 3, 2026 · 8 min read
Video Rendering Aspect Ratio AI Video Canvas FFmpeg

Modern ad campaigns require video creative exports across multiple screen formats: vertical 9:16 for TikTok/Reels and widescreen 16:9 for YouTube/Desktop. Naively cropping a 9:16 video into 16:9 leads to awkward subject clipping, misplaced captions, and poor visual composition. In our AI video generation suite (powering tools like Hook Machine and UGC Pipeline), we built a dual aspect-ratio rendering architecture that dynamically adapts layouts while sharing voiceover synthesis and audio alignment.

Never crop vertical video into widescreen post-hoc. Render parallel spatial coordinate trees anchored to a single synthesized voiceover track.

Multi-Canvas Layout Engine

Rather than rendering one format and performing a secondary video crop, our layout engine maintains dual spatial coordinate trees. Key UI elements (avatars, titles, CTA overlays) are positioned relative to target aspect containers:

// Responsive canvas transformation based on target aspect ratio
export interface LayoutBounds {
  avatarBounds: { x: number; y: number; w: number; h: number };
  captionBottomOffset: number;
  fontSize: number;
}

export function calculateElementBounds(aspectRatio: '16:9' | '9:16', width: number): LayoutBounds {
  const isVertical = aspectRatio === '9:16';
  const height = isVertical ? width * (16 / 9) : width * (9 / 16);

  return {
    avatarBounds: isVertical 
      ? { x: width * 0.1, y: height * 0.15, w: width * 0.8, h: width * 0.8 }
      : { x: width * 0.05, y: height * 0.1, w: height * 0.8, h: height * 0.8 },
    captionBottomOffset: isVertical ? 120 : 45,
    fontSize: isVertical ? 28 : 22
  };
}

Isolating Audio Elements during Frame Capture

During headless DOM frame captures (using Puppeteer/Playwright canvas capture), inline HTML <audio> tags or visual media controls can interfere with render loops if rendered on-screen. We decoupled audio synthesis into an off-screen headless audio pipeline, combining visual frames and voice tracks strictly in FFmpeg post-processing.

FFmpeg Dual Export Pipeline

Visual frame sequences for 16:9 and 9:16 are rendered in parallel workers and merged with the master voiceover audio track in a single unified command pass:

// FFmpeg command to assemble dual aspect-ratio outputs from shared audio
ffmpeg -framerate 30 -i frames_916/%04d.png -i voiceover.wav -c:v libx264 -pix_fmt yuv420p output_916.mp4 \
       -framerate 30 -i frames_169/%04d.png -i voiceover.wav -c:v libx264 -pix_fmt yuv420p output_169.mp4

What I'd do differently

I would unify caption rendering via WebAssembly libass earlier instead of relying on separate canvas overlays for 16:9 vs 9:16. Libass subtitle tracks adapt smoothly across aspect ratios without requiring manual font size recalculations, as detailed in Seam-Free Video Splicing.

The pattern: single audio, adaptive canvases

Multi-format AI video generation relies on a single audio source of truth driving responsive visual layout trees. Combining dual-canvas rendering with clean audio isolation enables shipping TikTok and YouTube ready ads simultaneously.
