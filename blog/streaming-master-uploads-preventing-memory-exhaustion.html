Streaming Master Uploads to Disk: Preventing Memory Exhaustion in Video Pipelines

By Humza Tareen August 3, 2026 · 6 min read
Node.js Next.js Streaming Video Pipelines Performance

When processing high-definition video assets in modern web applications, memory management is frequently the silent bottleneck that causes production servers to crash unexpectedly under load. In our AI video generation platform, processing master video uploads originally relied on standard form-data parsers that buffered incoming files directly in memory before writing them to disk. As video uploads scaled beyond 10 MB, servers encountered sudden out-of-memory (OOM) exceptions and generic "Expected a 'video' file field" multipart parsing errors.

The In-Memory Buffering Bottleneck

Standard HTTP body parsers in frameworks like Next.js often store incoming file payloads in RAM buffers (such as Buffer.concat()) during request ingestion. While this approach works reliably for small images or JSON payloads, video files introduce distinct challenges:

  • Memory Spikes: Concurrent uploads of 50 MB to 200 MB master videos quickly consume node process heap allocations, triggering garbage collector stalls and eventual crashes.
  • Parser Payload Caps: Built-in body parsers enforce rigid memory buffer limits. Exceeding these limits truncates streams prematurely, confusing boundary parsers and returning unhelpful form field validation errors.

Refactoring to Disk Streaming

To resolve this, we refactored the master video ingest pipeline to stream incoming request chunks directly onto disk storage using Node.js ReadableStream and temporary file descriptors, bypassing process memory entirely:

// Stream incoming upload chunks directly to disk
import { createWriteStream } from 'fs';
import { pipeline } from 'stream/promises';
import { Readable } from 'stream';

export async function handleMasterUpload(req: Request, targetPath: string) {
  if (!req.body) throw new Error("Missing request body stream");

  const writeStream = createWriteStream(targetPath, { flags: 'w' });
  const nodeStream = Readable.fromWeb(req.body as any);

  // Pipe directly to disk with zero in-memory buffer aggregation
  await pipeline(nodeStream, writeStream);
}

Key Pipeline Hardening Steps

  1. Stream Chunking: Ingesting chunks incrementally keeps RAM consumption flat (typically under 15 MB) regardless of whether the master file is 10 MB or 2 GB.
  2. Disk Cleanup Lifecycle: Temporary files are tracked in a transient registry and automatically cleaned up if processing fails or succeeds, avoiding disk fill-up incidents.
  3. Explicit Route Configs: In Next.js App Router API handlers, disable body parsing for raw file endpoints to delegate stream control directly to Node.js stream utilities.

Impact & Metrics

Migrating to stream-to-disk architecture delivered immediate stability improvements across our video variant platform:

  • 0% Memory OOM Crashes: Peak memory utilization during 100 MB+ video uploads dropped from >1.5 GB down to a stable ~35 MB.
  • Support for High-Bitrate Assets: Master videos of arbitrary sizes can now be ingested and processed smoothly.
